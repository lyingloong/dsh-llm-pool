DSH 0.2.1-rc.5 · Node.js 22.19+ / 24 · MIT · 27 tests

Why

不是随机换渠道，
而是把路由决策放进插件里。

01

会话粘性，缓存优先

新会话按当前绑定数最少的成员分配，之后尽量固定。只有失败或能力不匹配才迁移，避免每次调用换渠道导致 KV cache 失效。

02

首 token 前自动切换

认证、配额、限流、5xx、超时等失败会记录冷却并换下一个候选；已经有可见输出后交给 DSH 的 durable retry，不拼接两个渠道。

03

能力合并，逐请求过滤

上下文和输出取最小，推理档位取交集并支持逐渠道映射，图片取并集。成员不满足当前请求时自动跳过。

How it works

一次调用，三层决策

  1. 统一模型DSH 照常校验上下文、推理档位和工具；会话记录的是 pool-a / model-a。
  2. 真实成员按会话绑定或全局均衡选出 provider-a；模型不匹配时单独分配覆盖成员。
  3. 失败回退首 token 前换下一个候选并冷却；已输出后终止，由 DSH 重试整个 step。
- id: llm-pool
  name: dsh-llm-pool
  config:
    providers:
      pool-a:
        displayName: Example Pool
        strategy: sticky
        members: [provider-a, provider-b]
        models:
          - id: model-a
            targets:
              provider-a: model-a
              provider-b: model-a-alt
