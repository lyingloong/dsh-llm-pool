DeepSeek Harness plugin

一个统一服务商，
底层轮询多个真实渠道

把 ustc、ustc-dhsun、ustc-qhwang 组合成一个 ustc-pool。会话默认粘在一个渠道上保住缓存，新会话全局均衡，调用失败自动切换。

安装
dsh plugin --profile web add dsh-llm-pool

把 web 换成你的 profile 名，例如 desktop。安装后刷新客户端。

Why

不是简单的“随机换渠道”

会话分配、能力合并、失败语义和缓存取舍都在插件里处理，不碰 DSH 核心。

统一 provider 与统一模型

模型选择器里出现的是 ustc-pool 和 deepseek-flash；每个成员可以映射到不同的实际模型 id。

会话粘性 + 全局均衡

新会话进入当前绑定最少的渠道；之后同一会话尽量固定。只有失败或能力不匹配才迁移，尽量保住 KV cache。

自动故障切换

首 token 前失败按错误类型换成员；已经输出内容后交给 dsh-llm-retry 重试整个 step，不拼接两个渠道的回复。

能力合并

上下文/输出取最小，推理档位取交集并可逐渠道映射，图片取并集；不匹配的成员在请求时跳过。

设置页里的管理面板

在 Settings → Models 底部直接建池、自动聚合成员模型、逐个映射、测试模型，查看分配和健康状态。

冷却与可观测

认证、配额、限流、5xx、超时等失败进入冷却；全部冷却时 fail-open 选最早恢复的。面板显示最近调用和实际成员。

How it works

一次调用发生什么

01

选择统一模型

会话的 provider/model 记录为 ustc-pool / deepseek-flash。DSH 正常校验上下文、推理档位和工具。

02

按会话选真实成员

新会话按全局负载选择成员；已有会话使用自己的绑定。成员不支持当前模型时，为该模型单独分配覆盖成员。

03

失败按类别处理

首 token 前失败换下一个候选并记录冷却；已有输出后终止，由 DSH 的 durable retry 重新执行 step。

Quick start

三步开始

  1. 准备真实渠道：在 DSH 里配置好 endpoint、key 和模型，例如 ustc / ustc-dhsun / ustc-qhwang。
  2. 创建统一服务商：在 Settings → Models 底部点“新增统一服务商”，选择成员，自动聚合模型并调整映射，保存。
  3. 在会话里选择它：打开 /model 或输入框模型菜单，选择 ustc-pool 下的统一模型。子代理和默认模型也可以选。
查看示例配置 → 运行时设计 → 
# profile patch
- id: llm-pool
  name: dsh-llm-pool
  config:
    providers:
      ustc-pool:
        displayName: USTC 统一池
        strategy: sticky
        members:
          - ustc
          - ustc-dhsun
          - ustc-qhwang
        models:
          - id: deepseek-flash
            targets:
              ustc: deepseek-flash
              ustc-dhsun: deepseek-flash
              ustc-qhwang: deepseek-flash
Trust

权限与边界

插件只在当前 DSH Host 内注册虚拟 provider，不接触 provider 密钥，不修改 DSH 安装。

无密钥真实请求走你已有的 provider route；不读取、不保存、不记录 key。
写配置需确认只有点击面板“保存”时才通过 configEditor 写入 profile 配置。
测试会计费面板的“测试”发起真实 provider 请求；其余状态保存在内存中。
无遥测没有额外上报；卸载后真实 provider 配置保持不变。
