The gap

你已经有渠道，
缺的是路由.

多配几个 provider 不难。难的是每个会话该用哪个、失败之后怎么办、能力不匹配时谁先跳过。

dsh-llm-pool 把这些决策收进 provider 层。会话、子代理和默认模型照常选择虚拟 provider，不需要改 DSH 核心，也不需要代理服务器。

What it does

一个服务商，三层决策.

01

会话粘性

同一会话尽量固定在一个成员上，前缀缓存不因每次调用换渠道而失效。新会话才进入全局均衡。

sticky by default
02

首 token 前切换

认证、配额、限流、5xx、超时会进入冷却并换下一个成员；已经输出内容后交给 DSH 的 durable retry，不拼接两个渠道。

failover before output
03

能力感知

上下文和输出取最小，推理档位取交集并支持逐成员映射，图片取并集。不满足当前请求的成员自动跳过。

capability merge

How it works

一次调用，
三步完成.

  1. 01

    DSH 请求统一模型

    会话记录 pool-a / model-a，上下文、推理档位和工具照常校验。

  2. 02

    池子选出真实成员

    新会话按当前绑定数均衡；已有会话用绑定；模型映射到该成员的实际 id。

  3. 03

    失败按阶段处理

    首 token 前换下一个候选并记录冷却；已输出后终止，由 DSH 重新执行整个 step。

Install

一条命令开始.

把 web 换成你的 profile 名。安装后刷新客户端，在 Settings → Models 底部打开“统一服务商池”。

dsh plugin --profile web add dsh-llm-pool

Test 会发起真实计费请求；插件不读取、不保存 provider key。

Boundaries

它不做什么.

不是新的模型供应商

虚拟 provider 复用你已有的真实路由，不代理请求，也不替换 provider 配置。

不保存 API key

请求仍由 DSH 的 provider 层发出；插件不读取、不记录、不上传密钥。

默认不是轮询

默认 sticky：尽量让一个会话固定一个成员。需要时可以切到 round-robin 或 failover。

不拼接两个回复

已经产生可见输出后失败，调用终止，由 DSH 重试整个 step；不会把两个渠道的内容接在一起。
